# aviationdata

Magazine d'enquêtes en données ouvertes sur le transport aérien : une page d'accueil (`web/index.html`), les archives (`web/enquetes/`, filtre par thème `?theme=`), une page À propos (`web/a-propos/`, charte, corrections, sources) et une page par enquête, chacune dans son dossier (`web/le-ciel-a-deux-vitesses/`, données DGAC ; `web/courant-jet/`, courant-jet et vols transatlantiques ; `web/facteur-humain/`, facteur humain dans les accidents, données NTSB). L'accueil met en tête la dernière enquête avec sa propre figure (aujourd'hui la mosaïque des accidents, `web/src/hf/mosaic.js`). Les pages en chapitres partagent `web/src/site/story.css` (chapeau, essentiel, parties, réponse) et `web/src/site/story.js` (numéros de chapitres, barre des parties, progression, partage) ; `check_site.py` liste les enquêtes dans `SLUGS`, à compléter à chaque nouvelle enquête. Une nouvelle enquête = un dossier + une entrée dans `ISSUES` (`web/src/site/issues.js`) : pages Vite, sommaire, pied de page, surtitre (n° et thème), signature, enquête précédente et suivante, archives, liste et outils de l'accueil, flux Atom et sitemap en découlent. Une correction de fait = une entrée datée dans `CORRECTIONS` (même fichier).

## Commandes

- `python3 etl/fetch.py` : télécharge les 3 jeux DGAC dans `data/raw/` (data.gouv.fr doit être joignable : en local ou dans GitHub Actions, pas dans la session cloud Claude).
- `python3 etl/build.py` : lit `data/raw/`, écrit `web/public/data/*.json`. `--demo` génère des données fictives clairement signalées.
- `python3 -m pytest -q` : tests ETL (fixtures) + tests de référence (sautés si `data/raw/` est vide).
- `cd web && npm run dev | build | test` : front Vite + d3 (vanilla), tests vitest.
- `python3 web/scripts/interact.py` : parcours Playwright de toutes les interactions (servir `web/dist` sur 127.0.0.1:4173) ; `web/scripts/story_shots.py DIR "#sel,..." [--mobile]` pour les captures.
- `python3 web/scripts/audit_numbers.py` : recalcule en Python chaque chiffre écrit dans le récit et le compare au texte affiché (même serveur).
- `python3 web/scripts/check_site.py` : accueil, anciens liens, magazine (sommaire, pied de page, À propos, flux Atom, retour à l'accueil sur téléphone), enquête courant-jet (liens, simulateur, explorateur, coûts, mobile) et chaque chiffre de son texte recalculé depuis `web/public/data/jet/*.json`.
- Facteur humain : `python3 etl/hf/ntsb.py` télécharge la base Access du NTSB (avall.mdb depuis 2008, Pre2008.mdb de 1982 à 2007 ; data.ntsb.gov répond depuis la session cloud) et exporte ses tables en CSV avec mdbtools (`mdb-export`) ; `python3 etl/hf/build_hf.py` écrit `web/public/data/hf/` en trois secondes ; `python3 web/scripts/check_hf.py` recalcule chaque chiffre du texte, la mosaïque et l'outil ; `python3 web/scripts/og_hf.py` refait `web/public/og-hf.jpg`.
- Courant-jet : `etl/jet/{opensky,era5_daily,era5,era5_levels,reanalysis,nao,radiosonde,nasa,prices,forecasts}.py` téléchargent dans `data/raw/` (hors session cloud si un hôte est bloqué), puis `python3 etl/jet/build_jet.py [--skip-stats]` écrit `web/public/data/jet/`, `web/src/jet/route.fixture.json` et `web/src/jet/sim.fixture.json` (`build_history.py`, `build_sim.py`, `build_cost.py`, `build_forecast.py` ; `--skip-stats` garde `sim_stats.json`, dix minutes de calcul). Dépendances Python hors stdlib : numpy, pandas, xarray, `openap` (vitesses et consommations), `xlrd` (classeur de l'EIA). `python3 web/scripts/og_jet.py` refait `web/public/og-jet.jpg`.
- `python3 promo/capture.py && python3 promo/render.py` : film promo (graphiques réels filmés image par image, horloge simulée), sortie dans `promo/out/` (non versionné).
- Reel LinkedIn 4:5 avec vidéos de fond : `python3 promo/capture.py --theme dark && python3 promo/reel_footage.py && python3 promo/render.py --page reel.html --size 1080x1350 --out promo/out/le-ciel-a-deux-vitesses-reel-4x5.mp4`. Les rushes Pexels (auteurs et liens dans `promo/reel.json`) sont téléchargés dans `promo/out/footage/` et ne doivent jamais être versionnés (licence : pas de redistribution).
- Déploiement : Vercel lit `vercel.json` (build `web/`, sortie `web/dist`) ; `SITE_URL` ou le domaine Vercel rend les balises og:image absolues. Pas d'`ignoreCommand` : Vercel ne construit que le dernier commit d'un push, et un `git diff HEAD^ HEAD` sautait tout push finissant par un commit hors `web/`.

## Contrat de données

- Le front ne lit que `web/public/data/*.json`. Toute clé ajoutée ou renommée se change dans `etl/build.py`, `tests/test_etl.py::test_outputs_match_json_contract` et `web/src/lib/data.js` en même temps.
- `meta.json.demo === true` => bandeau « données de démonstration » obligatoire dans l'UI.
- Ouverture du courant-jet : la course (`openMap`, `web/src/jet/maps.js`) fait voler les deux sens dans le champ figé de `hero.json` (`route` vers Paris, `west` vers New York, chacun sur sa route la plus rapide, `A.fastest_route` dans `build_hero`), convertit les minutes en tonnes et en euros avec `cost.json`, ne joue qu'une fois à l'écran (bouton « Rejouer », état final sans mouvement réduit) ; `check_site.py` attend la phrase finale et en recalcule les chiffres.
- Facteur humain : la page ne lit que `web/public/data/hf/`. `accidents.json` porte des cellules `[année, type de vol, gravité, masque, accidents, morts]` (bits du masque dans `etl/hf/codes.py` : personne 1, panne 2, environnement 4, organisation 8, état indésirable 16, avion mal utilisé 32, indéterminé 64) ; toute part du récit est une somme de cellules (`web/src/hf/facts.js`, refaite en Python dans `check_hf.py`). Une clé changée dans `build_hf.py` se change dans `facts.js`, `text.js` et `check_hf.py`. Partie « À la loupe » : `cases.json` donne, pour six accidents célèbres (`etl/hf/cases.py` : numéros NTSB, libellé français de chaque constat, la construction échoue s'il en manque un), tous les constats codés `[dans la cause probable, C/F, colonne, couche, famille HFACS, personne désignée, français, NTSB]`, et les couches citées par type d'enquête (cinquième lettre du numéro de dossier : M majeure, F régionale, L limitée, dictionnaire des données du NTSB) ; résumés, causes probables et suites, avec leurs sources, dans `web/src/hf/cases.js` ; schéma et tableau dans `web/src/hf/loupe.js`. Le schéma relie chaque constat à l'accident par le rail de sa colonne, jamais à un autre constat (le NTSB ne code aucun lien entre constats).
- Courant-jet : la page ne lit que `web/public/data/jet/` (JSON + champs de vent int8 `hero.bin`, `winds-<année>.bin`, ordre `[jour][u, v][lat][lon]` ; simulateur `sim/<jour>.bin`, ordre `[pas 6 h][niveau][u, v, t − 215][lat][lon]`). Une clé changée dans `etl/jet/build_*.py` se change aussi dans `web/src/jet/` et `web/scripts/check_site.py`. `cost.json` est obligatoire (toute l'enquête convertit les minutes en kilos et en euros) ; `sim_stats`, `history` et `forecast` sont facultatifs : la page masque leur chapitre s'ils manquent.

## Pièges connus

- Adresses propres : Vercel sert `/courant-jet` depuis `courant-jet/index.html` (cleanUrls, sans barre finale) ; le plugin `clean-urls` de `vite.config.js` fait de même en dev et en preview. Les pages vivent un dossier sous la racine : chemins des données via `asset()` (`web/src/lib/site.js`, lit `<meta name="site-root">`), jamais en dur.
- Les anciens liens `/#chapitre` de la première enquête sont redirigés par le script en tête de `web/index.html` ; ne pas réutiliser ces ancres sur l'accueil. Le choix d'aéroport par défaut ne réécrit pas l'ancre (`selection.set(code, { url: false })`).
- OpenSky (Zenodo 7923702) : usage non lucratif, aucune redistribution des données brutes ni identifiant d'avion (indicatif, icao24, immatriculation) : seuls des agrégats quittent `data/raw/`. Citer « The OpenSky Network, https://opensky-network.org » ; l'auteur doit signaler la publication à OpenSky.
- ERA5 de WeatherBench 2 est stocké `[time, longitude, latitude]` : `build_jet.py` transpose. ARCO-ERA5 (0,25°) pèse 118 Mo par heure et par variable : seulement quelques instantanés.
- La meilleure route existe en deux exemplaires (Python `etl/jet/analysis.py`, navigateur `web/src/jet/route.js`) : toute modification se fait dans les deux, `route.test.js` compare au fixture écrit par `build_jet.py`. Les temps quotidiens de `routing.json` sont calculés sur les mêmes champs int8 recadrés que ceux de l'explorateur, pour que la page et le texte tombent à la minute.
- Le simulateur existe aussi en deux exemplaires (`etl/jet/sim.py`, `web/src/jet/sim.js`), vérifiés par `sim.test.js` contre `sim.fixture.json`. Les coûts (`web/src/jet/cost.js`, recalculés dans `check_site.py`) : kérosène d'un vol = facteur CO2 long-courrier DGAC × distance × passagers-équivalents par mouvement de Paris-CDG–New York-JFK (série PAP, dernière année complète) ÷ 3,16 (OACI) ; prix = EIA $/gallon ÷ taux BCE, 0,8 kg/L. Prix américain, ordre de grandeur, le temps de vol n'y est pas compté. Tout chiffre en kilos ou en euros renvoie à l'encadré `#couts` (« D'où viennent ces kilos et ces euros », chapitre de l'écart) : cinq étapes sourcées tirées de `costSteps()` (`cost.js`), écrites par `writeCouts()` (`text.js`) et refaites dans `check_site.py` ; la course d'ouverture et le simulateur y pointent. Distance Paris-CDG–New York-JFK de `cost.js` = aéroports de `winds.json` (celle de la page, 5 834 km), la conversion par minute n'en dépend pas. Dans le simulateur, le kérosène sans vent est le même pour les quatre avions (moyenne DGAC) : seuls le Mach et la consommation relative par niveau (OpenAP) changent, et la note sous les cartes le dit. Votre route = arcs de grand cercle entre ses points (`waypointPath`, recopié dans `check_site.py`), égale à la ligne droite tant qu'on n'a rien déplacé (`state.onLine`) ; jamais de spline en latitude-longitude (elle rallongeait la ligne droite d'une minute).
- Problématique de l'enquête courant-jet : jouer avec le vent et le prévoir peut-il réduire le coût de certains vols ? Une seule conversion court dans tout le texte : une minute de croisière à FL340 = `kgPerMinute(cost)` kg de kérosène (≈ 99) = au prix de référence `cost.recent` (moyenne des douze derniers mois). Les gains de route viennent de `sim_stats` (meilleure route à FL340 contre ligne droite, 2019-2022) ; l'explorateur reste un modèle simplifié (vent de midi figé, 900 km/h) et le texte le dit. Ne pas présenter ces gains comme des économies restant à faire (les routes NAT suivent déjà les vents). Demande de l'auteur : un montant sans avion, nombre de vols, prix ni point de comparaison « n'a aucun sens ». Tout euro dit de quoi il est le kérosène (« de kérosène », jamais « rapporte ») et renvoie à ses hypothèses : le bilan annuel passe par `routeLedger()` (`cost.js`) et l'encadré `#bilan-calc` (avion, Mach, heures de départ lues dans les données, vols PAP de l'année, kg/min, €/t, facture en ligne droite), les notes de figure répètent ces hypothèses. Les euros du récit ne viennent que du simulateur, jamais de l'explorateur (`check_site.py` le vérifie) ; seule la course d'ouverture, un jour illustré, convertit ses propres minutes, hypothèses dans sa légende. Physique : plus bas l'air est plus chaud, donc à Mach égal l'avion va plus vite ; plus haut il consomme moins. Repère du seuil d'altitude : Eurocontrol Standard Inputs (coût moyen d'une minute de retard, 100 €, prix 2022, `JSOURCES.eurocontrol`).
- Prévisions (`build_forecast.py`) : chaque jour de 2020, route calculée sur le vent moyen du mois, HRES (ECMWF) ou Pangu-Weather émis 12 h ou 108 h avant, ou ERA5, à température standard, puis volée dans ERA5 ; `sim.best_route_stack` renvoie le chemin (`path`, `levels`). Les délais de WeatherBench 2 sont des heures entières (Pangu commence à 6 h). Pangu, entraîné sur ERA5, est avantagé quand ERA5 sert de juge : le texte le dit.
- Marges : `.wrap` porte le retrait horizontal ; une section qui le partage ne règle que `padding-block`, jamais `padding: X 0` (cela supprimait les marges entre 640 et 1 330 px). `check_site.py` mesure le texte collé aux bords.
- Ton éditorial (demande de l'auteur) : le récit dit ce qu'on apprend, jamais ce que montre un graphique ni comment se servir d'un outil ; un titre de figure est un constat (« Plus de vent de face, plus de minutes »), le sous-titre donne la mesure et l'unité, et le mode d'emploi va dans une ligne « Lecture : » sous le graphique (`lecture()` dans `web/src/jet/text.js`, `p.note.lecture` en HTML). Gabarit d'un chapitre (lisibilité) : titre = constat ; un court paragraphe d'ouverture (`#x-prose`, deux chiffres au plus) ; la figure ; puis deux ou trois paragraphes (`#x-after`, `.after-figure`) et les réserves de méthode dans un encadré « À savoir » (`.story-aside`) ; pas plus de deux chiffres par phrase, plus d'encadré de chiffres clés (`.keyfig`) dans les enquêtes en chapitres.
- Lisibilité (audit contraste, taille, cibles tactiles) : aucun texte sous 0,78rem ; liens et boutons d'au moins 32 px de haut sur téléphone ; un fond calculé (`color-mix`, cases du simulateur) reste assez clair pour un texte sombre plutôt que d'alterner texte clair et sombre (la zone du milieu ne passe 4,5:1 avec aucun des deux).
- Le vent animé (`particles`, `web/src/jet/wind.js`) est réglé en temps réel (`rate` en degrés par seconde pour 1 m/s), pas en images : sinon il va deux fois plus vite sur un écran à 120 Hz.
- Partials : `<!--site:nom-->` dans les HTML est remplacé à la construction (`web/src/site/partials.js`, plugin Vite) ; un nom inconnu fait échouer la construction. Sur l'accueil, les liens sont relatifs sans `./` (`courant-jet`), depuis une enquête `../`. Le menu « Sommaire » (`<dialog>`, `web/src/site/menu.js`) recopie les chapitres depuis `.topnav`, sauf si la page a des `main > .part` (courant-jet) : il lit alors parties et chapitres dans le DOM (`.chapter-num b`) et la `.topnav` ne donne que les parties ; sur téléphone la barre est masquée et seul le menu les donne.
- NTSB : depuis 2021 la base ne marque plus cause (C) ni facteur (F) ; seul `cm_inPc = T` dit qu'un constat est retenu dans la cause probable. L'enquête compte partout causes et facteurs (`cm_inPc`), et s'arrête à la dernière année où 90 % des accidents et des accidents mortels ont une cause probable (2023 en octobre 2026). Classer par les numéros (`category_no`, `subcategory_no`, `modifier_no`), jamais en coupant le libellé sur « - » (« anti-ice »). « Aircraft oper/perf/capability » (sous-catégorie 6) est un état indésirable de l'avion (paramètre non maintenu), pas une panne ; les modificateurs de mauvaise utilisation, d'entretien ou de carburant sont des gestes humains rangés côté avion (bit 32). Avant 2008 (`seq_of_events`), une personne = `Person_Code` 4000-4199 ; les deux grilles ne se raccordent pas et le texte le dit. Le rapprochement avec HFACS est celui de l'auteur ; le NTSB ne code pas les violations. Les parts comparent des causes, pas des risques (le nombre de vols de l'aviation générale n'est pas connu). Seuls les accidents survenus aux États-Unis comptent.
- Trappes (IGRA 2) : seuls les sondages de 00 h et 12 h UTC depuis 1973 ; un lâcher à 23 h compte pour 00 h le lendemain ; une valeur à 250 hPa supérieure de plus de 60 km/h aux deux niveaux voisins est écartée.
- Somme APT (départs + arrivées) = double comptage des passagers domestiques. Les totaux France viennent de LSN.
- Les lignes sous seuil de diffusion (aéroports < 1 000 pax/mois, compagnies < 10 000) restent dans les totaux, jamais dans les classements.
- Un petit aéroport peut passer sous le seuil certains mois : afficher le trou, ne pas interpoler.
- La série PAP (paires d'aéroports) exclut les liaisons à moins de 3 opérateurs ou dominées à plus de 85 % : elle ne sert qu'aux cartes de liaisons (France, aéroport) et au chargement moyen d'un vol Paris-CDG–New York-JFK (courant-jet), jamais aux totaux, et le texte le précise.
- Les fichiers DGAC peuvent être en `;` et en cp1252 : `etl/dgac.py` normalise, et échoue bruyamment si une colonne attendue manque.
- data.gouv.fr est injoignable depuis la session cloud Claude (connexion coupée après le CONNECT) : passer par un relais `DGAC_RELAY_URL/TOKEN/KEY` (voir `etl/fetch.py`), jamais commité.
- Les CSV CO2 (EMI_TOT, EMI_UNI) sont au format large, une ligne par segment, sans unité dans l'en-tête : Mt vs g/Peq-km se distinguent par l'ordre de grandeur.
- Dans LSN, le domestique n'existe qu'agrégé par faisceau (MET_RAD, MET_TRA, MET_OM, OM_OM), pas par liaison.
- Les noms DGAC sont en majuscules sans accents : `pretty_name()` + table `ACCENTS` dans `etl/build.py`.
- Aéroports fermés absents d'OurAirports : coordonnées dans `data/ref/airports_manual.csv`.
- Les faits extérieurs aux données (taxe TSBA, Ormuz, Ryanair ; record BA112, North Atlantic Tracks, Williams 2016, Prosser 2023 pour le courant-jet ; Heinrich 1931, SHELL, Reason 1990, HFACS 2000, TEM, Dekker 2014, 49 CFR 830.2 et les six accidents de « À la loupe » pour le facteur humain) sont datés et sourcés dans `sources.js`, `web/src/jet/sources.js`, `web/src/hf/sources.js` et `web/src/hf/cases.js` ; les vérifier avant toute mise à jour du texte, jamais de lien de cause affirmé.
- Photo de l'auteur : publiée sur le site à sa demande (`web/public/auteur.jpg`) ; le film lit sa propre copie dans `promo/out/portrait.jpg` (non versionnée) ; un graphique filmé dans une grille `.grid-2` doit passer la grille sur une colonne (CSS de scène), sinon le panneau voisin déborde dans l'image.
- Une animation d'entrée (whileVisible, IntersectionObserver) ne joue qu'une fois : `promo/capture.py` filme les scènes dans l'ordre de la page pour ne pas la consommer avant sa scène.
- Espaces françaises : `watchFrenchSpacing` (`web/src/lib/ui.js`) pose l'espace fine avant ? ! : ; et entre chiffre et unité sur tout le DOM ; Archivo et Source Serif dessinent U+202F trop étroite, d'où `web/src/fonts/nnbsp.woff` (`web/scripts/make_nnbsp_font.py`) déclarée avec `unicode-range: U+202F`. Les scripts de test comparent les textes après avoir normalisé U+202F et U+00A0.
